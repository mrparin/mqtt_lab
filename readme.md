# MQTT Lab — ESP32 อ่านเซ็นเซอร์และควบคุมรีเลย์

โปรเจกต์นี้ใช้ ESP32 อ่านอุณหภูมิและความชื้นจาก DHT22 แล้วส่งข้อมูลผ่าน MQTT ประมาณทุก 5 วินาที อีกด้านหนึ่งก็รอรับคำสั่งเปิด–ปิดรีเลย์จากระบบหลังบ้าน เมื่อทำตามคำสั่งแล้วจะส่งข้อความตอบรับกลับไป ค่าเซ็นเซอร์และสถานะรีเลย์แสดงทั้งบน LCD และ Serial Monitor

เอกสารนี้อ้างอิงการทำงานใน `src/main.cpp` ปัจจุบัน ตัวอย่างข้อมูลเป็นค่าจำลองสำหรับอธิบาย ไม่ใช่ผลที่อ่านจากบอร์ดจริง

## ค่าที่ใช้ในโปรเจกต์

| รายการ | ค่า |
|---|---|
| บอร์ด | ESP32 DOIT DevKit V1 |
| MQTT broker | `192.168.1.5` พอร์ต `1883` |
| MQTT client ID ของบอร์ด | ค่า Device ID จาก Portal (ค่าเริ่มต้น `dev01`) |
| ปุ่มตั้งค่า WiFi ใหม่ | BOOT / GPIO 0 กดค้างอย่างน้อย 3 วินาทีแล้วปล่อยขณะโปรแกรมทำงาน |
| เซ็นเซอร์ | DHT22 ต่อขาสัญญาณที่ GPIO 15 |
| รีเลย์ | ขาควบคุม GPIO 5 |
| LCD | I2C address `0x27` ขนาด 20 ตัวอักษร × 4 บรรทัด |
| Serial Monitor | `115200` baud |

ตั้งค่า WiFi ผ่าน WiFiManager โดยไม่ต้องใส่ SSID/password ในโค้ด ส่วน MQTT Server ต้องเป็นที่อยู่ของ broker ที่เครื่องทดสอบและ ESP32 เข้าถึงได้ โค้ดนี้เชื่อมต่อ MQTT พอร์ต 1883 โดยไม่ได้ส่ง username/password

## การตั้งค่า WiFi และ MQTT ผ่าน WiFiManager

1. เปิดบอร์ด โปรแกรมจะลองเชื่อมต่อ WiFi ที่บันทึกไว้ หากยังไม่มีค่าหรือเชื่อมต่อไม่ได้ จะเปิดเครือข่าย `ESP32_SmartFarm` ซึ่งไม่มีรหัสผ่าน
2. ใช้โทรศัพท์หรือคอมพิวเตอร์เชื่อมต่อเครือข่ายนี้ หากหน้าตั้งค่าไม่เปิดเอง ให้เปิด `http://192.168.4.1` ในเบราว์เซอร์
3. เลือก Configure WiFi เลือกเครือข่าย WiFi 2.4 GHz และกรอกรหัสผ่าน พร้อมตรวจสอบค่าต่อไปนี้ก่อนกด Save

| ช่องใน Portal | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| MQTT Server IP | `192.168.1.5` | IP หรือ hostname ของ broker |
| Farm Name | `farm1` | ชื่อฟาร์มใน MQTT topic |
| Zone Name | `zoneA` | ชื่อโซนใน MQTT topic |
| Device ID | `dev01` | ชื่ออุปกรณ์ใน topic และ MQTT client ID ต้องไม่ซ้ำกับอุปกรณ์อื่น |

แต่ละช่องรับได้สูงสุด 39 ไบต์ แนะนำให้ใช้ตัวอักษรอังกฤษและตัวเลข Farm/Zone/Device ต้องไม่ว่างและไม่มี `/`, `+`, `#` หากกรอกไม่ถูกต้องโปรแกรมจะใช้ค่าเดิม ช่อง MQTT Server ที่ว่างจะใช้ค่าเดิมเช่นกัน

เมื่อเชื่อมต่อ WiFi สำเร็จ โปรแกรมจะบันทึก Custom Parameters ลง Preferences (NVS) จึงยังคงอยู่หลังปิด–เปิดบอร์ด ส่วน SSID/password บันทึกโดย WiFiManager การสร้าง topic ใช้รูปแบบ `<farm>/<zone>/<device>/telemetry`, `/cmd`, `/ack`, `/status` ตัวอย่าง MQTT ด้านล่างใช้ค่าเริ่มต้น หากเปลี่ยนชื่อใน Portal ต้องเปลี่ยน topic ที่ใช้ทดสอบตามด้วย

### ตั้งค่า WiFi ใหม่ด้วยปุ่ม BOOT

ขณะที่โปรแกรมทำงาน ให้กด BOOT ค้างอย่างน้อย 3 วินาทีแล้วปล่อย โปรแกรมจะปิดรีเลย์ ล้างข้อมูล WiFi เดิม และรีสตาร์ท จากนั้นเชื่อมต่อ `ESP32_SmartFarm` และตั้งค่าใหม่ตามขั้นตอนข้างต้น ค่า MQTT/Farm/Zone/Device เดิมจะยังอยู่และแก้ไขได้ใน Portal การกดสั้นกว่า 3 วินาทีไม่มีผล

เฟิร์มแวร์รุ่นนี้ตรวจปุ่มด้วย task แยกทุกประมาณ 10 มิลลิวินาทีและ debounce 30 มิลลิวินาที จึงจับการกดได้ระหว่างรอ WiFi/MQTT เมื่อครบ 3 วินาที Serial จะแสดง `BOOT held for 3 seconds. Release BOOT to reset WiFi.` และ LCD จะแสดง `Release BOOT` เมื่อโปรแกรมหลักกลับมาทำงาน ต้องปล่อยปุ่มจึงรีสตาร์ท หากโปรแกรมหลักกำลังรอการเชื่อมต่อ การล้างค่าอาจตามมาหลังการรอนั้นสิ้นสุด

หลังอัปโหลดและกด EN ให้ตรวจ Serial ที่ 115200 ว่ามี `Firmware: BOOT WiFi reset v2 (hold 3s, then release)` เพื่อยืนยันว่าบอร์ดใช้เฟิร์มแวร์ใหม่ หากกดแล้วไม่มี `BOOT pressed` ให้ตรวจว่าอัปโหลดเข้าบอร์ดถูกตัว และปุ่ม BOOT ของบอร์ดนั้นต่อ GPIO 0 ลง GND จริง (ห้ามใช้ปุ่ม EN แทน)

อย่ากด BOOT ค้างระหว่างเปิดเครื่องหรือกด EN/RESET เพราะ GPIO 0 เป็นขาเลือกโหมดบูตและอาจเข้าสู่โหมดดาวน์โหลดเฟิร์มแวร์ หากเกิดขึ้น ให้ปล่อย BOOT แล้วกด EN อีกครั้ง อ้างอิง [คู่มือโหมดบูต ESP32](https://docs.espressif.com/projects/esptool/en/latest/esp32/advanced-topics/boot-mode-selection.html)

โปรแกรมกำหนดเวลาลองเชื่อมต่อ WiFi 20 วินาที และเวลา Portal 180 วินาที (WiFiManager อาจยืดเวลาขณะมีการใช้งานหน้าเว็บ) หากออกจาก Portal โดยยังเชื่อมต่อไม่ได้ โปรแกรมจะรีสตาร์ทแล้วลองใหม่ ระหว่างอยู่ใน Portal จะยังไม่อ่านเซ็นเซอร์หรือรับคำสั่ง MQTT เมื่อ WiFi หลุดระหว่างใช้งาน จะใช้การเชื่อมต่อใหม่อัตโนมัติของ WiFi; หากต้องการเปลี่ยนเครือข่ายให้ใช้ BOOT

รายละเอียดไลบรารีดูได้จาก [WiFiManager](https://github.com/tzapu/WiFiManager)

## 1. Topic แต่ละหัวข้อ

Topic เปรียบเหมือนชื่อช่องรับ–ส่งข้อความ โครงสร้าง `farm1/zoneA/dev01/...` หมายถึงฟาร์ม `farm1` โซน `zoneA` อุปกรณ์ `dev01` ส่วนท้ายบอกประเภทของข้อความ

| Topic | ใครส่ง → ใครรับ | ใช้ทำอะไร | Retain |
|---|---|---|---|
| `farm1/zoneA/dev01/telemetry` | ESP32 → ระบบหลังบ้าน | ส่งอุณหภูมิ ความชื้น และสถานะที่สั่งรีเลย์ | ไม่ใช้ |
| `farm1/zoneA/dev01/cmd` | ระบบหลังบ้าน → ESP32 | สั่งเปิดหรือปิดรีเลย์ | ตัวอย่างทดสอบไม่ใช้ |
| `farm1/zoneA/dev01/ack` | ESP32 → ระบบหลังบ้าน | ตอบรับหลังประมวลผลคำสั่งรีเลย์ | ไม่ใช้ |
| `farm1/zoneA/dev01/status` | ESP32 หรือ broker → ระบบหลังบ้าน | แจ้งสถานะการเชื่อมต่อ online/offline | ใช้ |

Retain คือการให้ broker เก็บข้อความล่าสุดของ topic ไว้ คนที่เข้ามารับฟังภายหลังจึงได้รับข้อความนั้นทันที ในโปรเจกต์นี้ใช้กับ `status` เท่านั้น

### telemetry — ข้อมูลเซ็นเซอร์

ตัวอย่างข้อความ:

```json
{"temp":28.5,"hum":65.2,"relay_state":false}
```

- `temp` คืออุณหภูมิ หน่วยองศาเซลเซียส
- `hum` คือความชื้นสัมพัทธ์ หน่วยเปอร์เซ็นต์
- `relay_state` คือสถานะที่โปรแกรมสั่งรีเลย์ `true` = เปิด และ `false` = ปิด

ส่งเมื่ออ่านอุณหภูมิและความชื้นได้ทั้งคู่ หาก DHT22 อ่านไม่สำเร็จ รอบนั้นจะไม่ส่ง telemetry และจะแสดงข้อผิดพลาดใน Serial Monitor

### cmd — คำสั่งควบคุม

เปิดรีเลย์:

```json
{"cmd":"relay","state":1}
```

ปิดรีเลย์:

```json
{"cmd":"relay","state":0}
```

ใช้ `state` เป็นจำนวนเต็ม `1` หรือ `0` ตามตัวอย่าง หากไม่มีฟิลด์นี้หรือชนิด/ค่าไม่ถูกต้อง โปรแกรมจะไม่เปลี่ยนรีเลย์และไม่ส่ง ack โดยจะแสดง `Invalid relay state` ใน Serial Monitor

ถ้า `cmd` ไม่ใช่ `relay` โปรแกรมจะไม่ทำอะไรและไม่ส่ง ack หาก JSON ผิดรูปแบบ จะพิมพ์ `JSON Parse Error` ใน Serial Monitor แล้วหยุดประมวลผลข้อความนั้น

### ack — ข้อความตอบรับ

ตัวอย่างหลังสั่งเปิด:

```json
{"cmd":"relay","status":"success","executed_state":true}
```

`ackDoc` เป็นตัวแปรที่ใช้ประกอบข้อความนี้ จากนั้น `serializeJson()` แปลงเป็นข้อความก่อนส่งไปที่ topic `ack`

`success` หมายถึงโปรแกรมรับคำสั่งและสั่ง GPIO แล้ว ส่วน `executed_state` บอกสถานะที่สั่ง ยังไม่ได้ยืนยันว่าหน้าสัมผัสรีเลย์เปลี่ยนหรืออุปกรณ์ปลายทางทำงานจริง เพราะโปรเจกต์นี้ยังไม่มีเซ็นเซอร์ feedback เช่น current sensor

### status — สถานะการเชื่อมต่อ

เมื่อ ESP32 เชื่อมต่อ broker สำเร็จ จะส่ง:

```json
{"status":"online"}
```

ตอนเชื่อมต่อ ESP32 จะฝากข้อความ Last Will and Testament (LWT) ไว้กับ broker ด้วย หากการเชื่อมต่อขาดโดยไม่ได้ disconnect ตามปกติ broker จะส่ง:

```json
{"status":"offline"}
```

ข้อความ offline อาจไม่ได้ปรากฏทันทีที่ถอดไฟ เพราะ broker ต้องตรวจพบว่าการเชื่อมต่อขาดก่อน ทั้ง online และ offline ใช้ Retain จึงอ่านสถานะล่าสุดได้แม้เพิ่งเปิดตัวรับฟัง แต่สถานะนี้บอกเรื่องการเชื่อมต่อ ไม่ได้ยืนยันสุขภาพเซ็นเซอร์หรือรีเลย์

## ตัวอย่างส่งคำสั่งเพื่อทดสอบ

โปรแกรมนี้รับคำสั่งผ่าน MQTT ยังไม่มี HTTP API จึงไม่มี URL สำหรับยิงด้วย `curl` หรือ HTTP POST โดยตรง ตัวอย่างด้านล่างใช้ `mosquitto_pub` ส่งข้อความ และ `mosquitto_sub` รับข้อความจาก broker

เตรียม Mosquitto clients ให้เรียกสองคำสั่งนี้ได้จาก Terminal และให้เครื่องทดสอบเข้าถึง `192.168.1.5:1883` ได้ หาก broker ใช้ IP อื่น ให้แก้ทั้งในคำสั่งและใน `mqtt_server`

### ขั้นที่ 1: เปิดหน้าต่างรับข้อความ

รันใน Terminal หน้าต่างแรก แล้วปล่อยไว้:

```powershell
mosquitto_sub -h 192.168.1.5 -p 1883 -t 'farm1/zoneA/dev01/#' -v
```

`#` รับทุก topic ใต้ `dev01` ส่วน `-v` ให้แสดงชื่อ topic พร้อมข้อความ จึงเห็นทั้ง telemetry, cmd, ack และ status ได้ในหน้าต่างเดียว

ถ้าต้องการดูเฉพาะข้อความตอบรับ ใช้:

```powershell
mosquitto_sub -h 192.168.1.5 -p 1883 -t 'farm1/zoneA/dev01/ack' -v
```

### ขั้นที่ 2: ส่งคำสั่งเปิด–ปิด

เปิด Terminal อีกหน้าต่างหนึ่ง แล้วรันคำสั่งต่อไปนี้ใน PowerShell ใช้ส่ง JSON ผ่าน stdin เพื่อลดปัญหาเครื่องหมายคำพูดเมื่อเรียกโปรแกรมภายนอกบน Windows

เปิดรีเลย์:

```powershell
'{"cmd":"relay","state":1}' | mosquitto_pub -h 192.168.1.5 -p 1883 -t 'farm1/zoneA/dev01/cmd' -s
```

ผลตอบรับที่ควรเห็นในหน้าต่างแรก:

```text
farm1/zoneA/dev01/ack {"cmd":"relay","status":"success","executed_state":true}
```

ปิดรีเลย์:

```powershell
'{"cmd":"relay","state":0}' | mosquitto_pub -h 192.168.1.5 -p 1883 -t 'farm1/zoneA/dev01/cmd' -s
```

ผลตอบรับที่ควรเห็น:

```text
farm1/zoneA/dev01/ack {"cmd":"relay","status":"success","executed_state":false}
```

LCD และ Serial Monitor ควรเปลี่ยนสถานะทันที ส่วน `relay_state` ใน telemetry จะเปลี่ยนตามในรอบอ่านเซ็นเซอร์ถัดไปที่อ่านสำเร็จ

อย่าใส่ `-r` กับคำสั่งควบคุมในการทดสอบนี้ เพราะคำสั่งที่ถูกเก็บแบบ Retain อาจส่งซ้ำให้ ESP32 ตอนกลับมาเชื่อมต่อได้ และอย่าใช้ client ID เดียวกับ Device ID ของบอร์ด (ค่าเริ่มต้น `dev01`) กับเครื่องทดสอบ เพราะจะชนกับบอร์ด

### ขั้นที่ 3: ดูค่าเซ็นเซอร์และการเชื่อมต่อ

รับค่าเซ็นเซอร์อย่างเดียว:

```powershell
mosquitto_sub -h 192.168.1.5 -p 1883 -t 'farm1/zoneA/dev01/telemetry' -v
```

รับสถานะการเชื่อมต่ออย่างเดียว:

```powershell
mosquitto_sub -h 192.168.1.5 -p 1883 -t 'farm1/zoneA/dev01/status' -v
```

เมื่อบอร์ดเชื่อมต่อสำเร็จควรเห็น `online` หากทดสอบตัดไฟบอร์ด ให้รอ broker ตรวจพบการหลุดก่อน จึงจะเห็น `offline` เมื่อเปิดบอร์ดกลับมาและต่อ MQTT สำเร็จ สถานะจะกลับเป็น `online`

สำหรับ telemetry, ack และ status ให้รับฟังข้อมูลที่บอร์ดส่ง การส่งข้อมูลจำลองเข้า topic เหล่านี้เองจะไม่ได้ทำให้ ESP32 อ่านเซ็นเซอร์หรือเปลี่ยนสถานะ และอาจทำให้ผู้รับเข้าใจว่าเป็นข้อมูลจริงจากบอร์ด

รายละเอียดตัวเลือกคำสั่งดูได้จากคู่มือ [mosquitto_pub](https://mosquitto.org/man/mosquitto_pub-1.html) และ [mosquitto_sub](https://mosquitto.org/man/mosquitto_sub-1.html)

## 2. หน้าที่ของแต่ละฟังก์ชัน

### setup() — เตรียมอุปกรณ์ตอนเปิดเครื่อง

ทำงานหนึ่งครั้งหลังเปิดเครื่องหรือรีเซ็ต เริ่ม Serial ที่ 115200 ตั้ง BOOT เป็น INPUT_PULLUP เปิด LCD ตั้งขารีเลย์เป็น OUTPUT แล้วสั่ง LOW เริ่ม DHT22 โหลด Custom Parameters จาก Preferences และสร้างช่องกรอกใน WiFiManager จากนั้นเรียก `autoConnect("ESP32_SmartFarm")`

เมื่อ WiFi ต่อสำเร็จ จึงกำหนด broker พอร์ต 1883 และบอก MQTT client ให้เรียก `callback()` เมื่อมีข้อความเข้ามา การเชื่อมต่อ MQTT จริงจะเกิดใน `reconnect()` ตอนเข้า `loop()`

โค้ดถือว่า HIGH คือเปิดรีเลย์ และ LOW คือปิด ต้องตรวจให้ตรงกับโมดูลที่ใช้ หากเป็นโมดูล active-low พฤติกรรมจริงจะกลับด้านจากที่โปรแกรมแสดง

### loadConfig() / saveConfig() — เก็บค่าตั้งถาวร

อ่านและบันทึก MQTT Server, Farm, Zone และ Device ลง Preferences แยกจากข้อมูล WiFi หลังเชื่อมต่อสำเร็จ `setup()` จะตรวจสอบค่าที่กรอก บันทึก และสร้าง topic ตามค่าปัจจุบัน

### checkResetButton() — ตั้งค่า WiFi ใหม่

`monitorBootButton()` จับเวลากดและส่งคำขอผ่านตัวแปร atomic ส่วน `checkResetButton()` เรียกใน `loop()` และลูปให้บริการ Portal ใน `setup()` เพื่อแสดงข้อความและทำงานเมื่อปล่อยหลังค้างอย่างน้อย 3 วินาที ปิดรีเลย์ ส่ง offline และ disconnect หาก MQTT ยังเชื่อมต่ออยู่ แล้วล้างเฉพาะ WiFi และรีสตาร์ทหลังปล่อยปุ่ม Custom Parameters ยังอยู่ การเข้าถึง WiFiManager/MQTT/LCD ทำจากโปรแกรมหลัก

### reconnect() — ต่อ MQTT และประกาศสถานะ

เมื่อ WiFi เชื่อมต่ออยู่ จะลองเชื่อมต่อ MQTT ด้วย client ID จาก `device_id` พร้อมฝาก LWT สำหรับสถานะ offline ถ้าต่อสำเร็จ จะส่ง online แบบ Retain และ subscribe topic `cmd` เพื่อรอรับคำสั่ง

ถ้าต่อไม่สำเร็จ จะพิมพ์ `failed, rc=...` แล้วกลับไปทำ `loop()` โดยเว้นอย่างน้อย 5 วินาทีก่อนลองใหม่ จึงยังตรวจปุ่มและอ่านเซ็นเซอร์ได้ ไม่มีลูปรอ MQTT จนกว่าจะสำเร็จ แต่การ connect แต่ละครั้งยังใช้เวลารอ TCP/DNS และการตอบกลับได้ โดยกำหนด MQTT socket timeout เป็น 3 วินาที

### callback(topic, payload, length) — รับคำสั่งและสั่งรีเลย์

MQTT client เรียกฟังก์ชันนี้เมื่อประมวลผลข้อความที่รับเข้ามา โดยส่งชื่อ topic, ข้อมูลข้อความ และความยาวของข้อความมาให้

การทำงานมีดังนี้:

1. แปลง payload จาก JSON เป็น `doc` ถ้าแปลงไม่ได้ ให้แสดงข้อผิดพลาดแล้วออกจากฟังก์ชัน
2. ตรวจว่าข้อความมาจาก topic `cmd`
3. อ่านฟิลด์ `cmd` และ `state` ถ้าเป็นคำสั่ง `relay` ให้ตั้ง `relayState` ตามค่า `state`
4. สั่ง GPIO 5 เป็น HIGH เมื่อเปิด หรือ LOW เมื่อปิด
5. สร้าง `ackDoc` แล้วส่งข้อความตอบรับไปที่ topic `ack`
6. เรียก `updateDisplay()` ให้หน้าจอแสดงสถานะใหม่ทันที

### updateDisplay() — แสดงค่าล่าสุด

นำ IP, `currentTemp`, `currentHum` และ `relayState` ไปแสดงบน LCD ทั้ง 4 บรรทัด พร้อมพิมพ์ข้อมูลเดียวกันใน Serial Monitor อุณหภูมิและความชื้นแสดงทศนิยมหนึ่งตำแหน่ง

ฟังก์ชันนี้ไม่ได้อ่านเซ็นเซอร์เอง ใช้ค่าล่าสุดที่เก็บไว้ในตัวแปร หากได้รับคำสั่งรีเลย์ก่อนอ่าน DHT22 สำเร็จครั้งแรก อุณหภูมิและความชื้นที่แสดงอาจยังเป็นค่าเริ่มต้น `0.0`

### loop() — งานที่วนทำตลอด

เริ่มจากตรวจ BOOT ด้วย `checkResetButton()` ตรวจการเชื่อมต่อ MQTT ถ้าหลุดให้เรียก `reconnect()` จากนั้นเรียก `client.loop()` เพื่อดูแลการเชื่อมต่อและประมวลผลข้อความขาเข้า ซึ่งอาจทำให้ `callback()` ถูกเรียก

ส่วนอ่านเซ็นเซอร์ใช้ `millis()` เทียบกับ `lastMsg` เมื่อผ่านไปมากกว่า 5,000 มิลลิวินาที จะอ่านอุณหภูมิและความชื้นจาก DHT22 ถ้าอ่านได้ทั้งคู่ จะเก็บค่าใหม่ สร้าง JSON ส่ง telemetry และอัปเดตหน้าจอ ถ้าอ่านไม่ได้ จะพิมพ์ `Failed to read from DHT sensor!` และใช้ค่าที่เคยเก็บไว้ต่อไป

การจับเวลารอบเซ็นเซอร์ไม่ได้ใช้ `delay(5000)` จึงเรียก `client.loop()` และตรวจ BOOT ได้ระหว่างรอรอบถัดไป แต่การต่อเครือข่ายแต่ละครั้งยังทำให้รอบงานล่าช้าได้ ขณะ MQTT หลุดยังอ่านและแสดงค่าเซ็นเซอร์ แต่ telemetry จะส่งไม่ได้และไม่มีการเก็บย้อนหลัง

## อ่านผลทดสอบอย่างไร

### ตรวจสอบความสามารถ WiFiManager บนบอร์ดจริง

1. อัปโหลดเฟิร์มแวร์ เปิด Serial Monitor ที่ 115200 และตั้งค่า WiFi ผ่าน `ESP32_SmartFarm`
2. เปลี่ยน MQTT/Farm/Zone/Device จากค่าเริ่มต้น เชื่อมต่อสำเร็จแล้วปิด–เปิดบอร์ด ตรวจว่า `--- Current Topics ---` และ broker ยังใช้ค่าที่ตั้งไว้
3. กด BOOT สั้นกว่า 3 วินาที ตรวจว่าบอร์ดไม่รีสตาร์ท จากนั้นกดค้างอย่างน้อย 3 วินาทีแล้วปล่อย ตรวจว่ารีเลย์ปิดและเปิด Portal ใหม่ โดยค่า Custom Parameters ยังอยู่
4. ทดสอบตอน broker ปิดอยู่และระหว่างเปิด Portal กด BOOT จน Serial แสดง `Release BOOT to reset WiFi` แล้วปล่อย ตรวจว่าคำขอไม่หายระหว่างรอเครือข่ายและรีสตาร์ทเมื่อโปรแกรมหลักกลับมาทำงาน
5. ตั้งค่า WiFi ใหม่แล้วตรวจ telemetry, cmd, ack และ status ตามตัวอย่าง เปลี่ยน topic/IP ให้ตรงกับค่าจริง

ตรวจสอบการคอมไพล์ด้วย `pio run` สำหรับ environment `esp32doit-devkit-v1` แล้วผ่าน การทำงานของปุ่ม, Portal, WiFi และอุปกรณ์ต่อพ่วงต้องยืนยันด้วยการทดสอบบนบอร์ดจริง

| สิ่งที่เห็น | ความหมาย |
|---|---|
| Serial เป็นตัวอักษรเพี้ยน | ตรวจว่า Monitor ตั้งเป็น 115200 และตรงกับ `Serial.begin()` |
| เห็นเครือข่าย `ESP32_SmartFarm` | บอร์ดรอตั้งค่า WiFi ให้เปิด `http://192.168.4.1` |
| `Attempting MQTT connection...failed, rc=...` | ต่อ broker ไม่สำเร็จ ตรวจ IP พอร์ต และการเข้าถึง broker |
| `Failed to read from DHT sensor!` | อ่าน DHT22 ไม่ได้ รอบนั้นไม่มี telemetry |
| เห็น cmd แต่ไม่เห็น ack | เห็นเพียงข้อความที่ส่งไป ยังไม่ยืนยันว่าบอร์ดรับ ตรวจการเชื่อมต่อ รูปแบบ JSON และค่า `cmd` |
| ack เป็น success แต่โหลดไม่ทำงาน | โปรแกรมสั่ง GPIO แล้ว ต้องตรวจโมดูลรีเลย์และอุปกรณ์จริงเพิ่มเติม |
